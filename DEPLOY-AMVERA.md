# Размещение сервера на Amvera

Amvera (https://amvera.ru) запускает Python-приложение из git-репозитория и даёт ему постоянную папку `/data` и адрес с HTTPS.
Здесь описано, как выложить игровой сервер FWSlot. Пакет собирается скриптом, никаких лишних файлов (клиент, арт, снимки) в него не попадает.

## 0. Прочтите до выкладки

- **Деньги.** Пакет стартует в режиме DEMO (игровые деньги, кошелёк выключен). Реальные TON включаются только переменными окружения (раздел 3).
  Азартные игры на деньги запрещены или требуют лицензии во многих странах (в России онлайн-казино запрещены), а правила хостинга обычно
  запрещают такие проекты. Условия Amvera я не проверял: перед включением реальных денег прочитайте их и убедитесь, что проект законен
  там, где вы им управляете и где играют ваши игроки. Демо-режим без выплат этих рисков не несёт.
- **Один экземпляр.** Состояние игроков лежит в `state.json` и `journal.jsonl` в `/data`. Сервер должен работать в одном экземпляре (не масштабировать).
- **Пароль админа** задавайте переменной окружения, длинный и уникальный. Панель `/admin` доступна из интернета (защита: вход по паролю,
  блокировка перебора, строгий CSP), поэтому слабый пароль недопустим.

## 1. Собрать пакет

```powershell
python tools/make_amvera_bundle.py --verify
```
Результат: папка `dist/amvera` (около 280 КБ). `--verify` проверяет, что код читается как Python 3.11 (версия из `amvera.yml`) и что пакет сам
по себе запускается: проверка здоровья, регистрация, спин, вход админа.

## 2. Создать приложение и выложить

1. В Amvera создайте проект: окружение Python, инструмент pip, версия 3.11. Тариф с постоянным хранилищем.
2. Скопируйте адрес git-репозитория проекта (вид `https://git.amvera.ru/<пользователь>/<проект>`).
3. Выложите содержимое `dist/amvera` как отдельный репозиторий:
```powershell
cd dist/amvera
git init -b master
git add -A
git commit -m "FWSlot server"
git remote add amvera https://git.amvera.ru/<пользователь>/<проект>
git push amvera master
```
   Amvera соберёт пакет по `amvera.yml`: `python server/run.py --host 0.0.0.0 --port 80 --data /data --trust-proxy`, порт 80, постоянная папка `/data`.
4. Включите в проекте домен с HTTPS (Amvera выдаёт адрес вида `<проект>-<пользователь>.amvera.io`, свой домен тоже можно подключить).

## 3. Переменные окружения (раздел «Переменные» проекта в Amvera)

| Переменная | Значение | Обязательно |
|---|---|---|
| `FWSLOT_ADMIN_PASSWORD` | пароль админа (длинный, уникальный) | да |
| `FWSLOT_WALLET` | `off` (по умолчанию, демо) / `ton` (реальные TON) | нет |
| `FWSLOT_TON_ADDRESS` | адрес кошелька оператора для депозитов | при `ton` |
| `FWSLOT_TON_NETWORK` | `mainnet` или `testnet` | при `ton` |
| `FWSLOT_TON_API_URL` | `https://toncenter.com` или `https://testnet.toncenter.com` (сеть должна совпадать) | при `ton` |
| `FWSLOT_TON_API_KEY` | ключ TON Center (без него публичный лимит запросов) | желательно |
| `FWSLOT_TRUST_PROXY` | `1`, если запуск без флага `--trust-proxy` | нет |

Остальное (лимиты ставок, требование оборота) задаётся флагами команды в `amvera.yml`: `--max-real-bet`, `--wager-mult`, `--no-gamble`, `--no-rewards`.
Ключей кошелька на сервере нет и не должно быть: выплаты выводов делает человек из кабинета администратора.

## 4. Проверить после запуска

- `https://<адрес>/api/health` отвечает `{"ok": true}`.
- `https://<адрес>/admin` открывает кабинет, вход по `FWSLOT_ADMIN_PASSWORD`.
- Регистрация и спин через клиент (раздел 5) проходят, в кабинете виден игрок и раунд.
- Перезапуск проекта не стирает игроков: данные лежат в `/data`.
- Регулярно скачивайте копию `/data` (`state.json`, `journal.jsonl`): это единственное хранилище.

## 5. Клиент для игроков

Клиент берёт адрес сервера из `--server=URL`, переменной `FWSLOT_SERVER` или файла `client/data/server_url.txt` (одна строка). Для сборки игрокам:
```powershell
Set-Content client\data\server_url.txt "https://<адрес>" -Encoding ascii
godot --headless --path client --export-release "Windows Desktop"      # результат: build/FWSlot.exe
```
Без файла клиент играет демо-запись без сервера. Файл `data/*.txt` входит в сборку (фильтр в `export_presets.cfg`).

## 5b. Игра в браузере и на телефоне (/play/)

Сервер сам раздаёт браузерную версию игры: `https://<адрес>/play/` (адрес `/` перенаправляет туда). Игрок открывает ссылку в браузере телефона или
компьютера, ничего не устанавливая. Клиент берёт адрес сервера из адреса страницы, файл `server_url.txt` для веба не нужен.
- Сборка: в Godot пресет **Web** (без потоков) экспортируется в `server/web/` (`godot --headless --path client --export-release Web`),
  затем `python tools/make_amvera_bundle.py --verify` кладёт её в пакет. Размер сборки около 63 МБ, по сети идёт около 30 МБ (сервер сжимает gzip и отдаёт ETag).
  Шаблоны экспорта Web для Godot 4.7.2 должны стоять в `%APPDATA%/Godot/export_templates/4.7.2.stable/`.
- **Ограничения веб-версии:** личный кошелёк создаётся только в приложении для компьютера (в браузере нет потоков, окно показывает пояснение);
  портретная раскладка для телефона ещё не нарисована: на вертикальном экране видна обрезанная горизонтальная картинка, играть удобнее с телефоном, повёрнутым на бок.
- Проверено: страница и игра запускаются в Edge (окно входа рисуется). На настоящем телефоне не проверялось.

## 6. Что ещё нужно до публичного запуска

HTTPS уже даёт Amvera. Остаётся: база данных вместо JSON-файлов (если игроков станет много), двухфакторный вход админа, лимиты ответственной игры,
для реальных денег лицензия, KYC / AML и юридическая оценка. Список: `docs/GDD.md` раздел 10.21 и README.
