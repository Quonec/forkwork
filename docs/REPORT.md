# Отчёт по составляющим ForkWork Scanner

Версия **0.9.30** · дата отчёта 2026-10-20 · коммит `f88bbd6` (репозиторий разработки `forkwork-scanner`, зеркало в `forkwork`).

Отчёт собран по коду, git-истории и сборке. Работу сайта в продакшене на дату отчёта проверить не удалось (с рабочего места не было доступа к российским сайтам), последняя подтверждённая проверка: 2026-10-08, версия 0.9.30 открывалась, `/api/health` отвечал `{"ok":true}`.

## 1. Что это

Foodtech-сайт на одной кодовой базе: сканер КБЖУ блюда, дневник питания, карта и каталог заведений Москвы, повара с заказами, эфиры, личные чаты, рецепты, AI-ассистент. Роли: заказчик, повар, менеджер, администратор.

## 2. Технологический стек

| Слой | Технология |
|---|---|
| Фреймворк | Next.js 16 (App Router), React 19, TypeScript (strict) |
| Стили | Tailwind CSS 4, палитра светлой охры с жёлтым акцентом |
| База | SQLite через встроенный `node:sqlite` (нужен Node ≥ 22.5), файл `forkwork.db` |
| Карта | Яндекс.Карты JS API 2.1 |
| AI | `@anthropic-ai/sdk` (модели Claude), при отсутствии ключа работает детерминированная эвристика |
| Авторизация | cookie-сессии (httpOnly), bcrypt, ограничение попыток входа |
| Тесты и CI | vitest, GitHub Actions (tsc, тесты, сборка) |
| Деплой | Docker на Amvera Cloud, порт 3000, постоянный том `/data` |

Объём: около 19,7 тыс. строк TypeScript/TSX; 29 страниц, 40 API-маршрутов, 35 компонентов интерфейса.

## 3. Составляющие и их готовность

## 6. Деплой и окружение

- Сборка по `Dockerfile` (Node 24, два этапа), конфигурация `amvera.yaml`, порт 3000, том `/data` (база и секретное хранилище), `HEALTHCHECK` на `/api/health`.
- Сайт собирается из `main` этого репозитория: любой пуш запускает пересборку (около 1–3 минут недоступности).
- Основные переменные: `ADMIN_EMAIL`, `ADMIN_PASSWORD` (первый запуск), `ANTHROPIC_API_KEY`, `CHAT_VAULT_KEY`, `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`, `NEXT_PUBLIC_SITE_URL`; флаги демо-режима `SEED_DEMO`, `NEXT_PUBLIC_SHOW_DEMO`, `NEXT_PUBLIC_SHOW_DEMO_STAFF` (описаны в `docs/DEPLOY.md`).
- Файл CI (`.github/workflows`) в этот репозиторий не переносится (у токена публикации нет права `workflow`); он лежит в репозитории разработки.

## 8. Открытые вопросы и риски

1. **Сканер не распознаёт блюда по-настоящему** (заглушка). Пока провайдер не выбран, дневник и советы по питанию строятся на условных данных. Для публичного запуска либо подключить реальное распознавание, либо прямо пометить режим.
2. **Демо-режим на публичном сайте.** `SEED_DEMO` предназначен для закрытого показа; на публичном сайте демо-данные и служебные демо-аккаунты нужно отключить и заменить аккаунтами с собственными паролями.
3. **AI-функции** зависят от секрета `ANTHROPIC_API_KEY` на сервере; его наличие на хостинге не проверено.
4. **Юридическая часть** перед публикацией: политика конфиденциальности, пользовательское соглашение, источники данных (дословные отзывы с чужих сайтов, данные поваров, платежи). Нужна проверка юристом.
5. **Ключ Яндекс.Карт** публичный и должен быть ограничен по домену в кабинете Яндекса (статус не подтверждён).
6. **Оплата** только внутри кошелька, без платёжной системы.
7. **Поллинг вместо WebSocket** для чатов и эфиров; **офлайн-режима и service worker нет**.
8. **Данные топа:** надпись «прочитано» в карточках для новых партий показывает старую дату; часть отзывов обрезана.

## 9. Ближайшие шаги

1. Выбрать и подключить провайдера распознавания блюд (оценка на 30 блюдах).
2. Закрыть демо-режим на публичном сайте и проверить секреты хостинга.
3. Юридические страницы, обёртка для магазинов (TWA или Capacitor), скриншоты, аккаунты разработчика.
4. Определить приоритетные сегменты аудитории (по итогам встречи 2026-10-08) и привязать к ним порядок разработки.
5. Продолжить наполнение топа и восстановить список кандидатов.
6. Расширить автотесты: сканер, API, кабинеты.
