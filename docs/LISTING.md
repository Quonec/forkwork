# Подготовка к листингу

Сейчас ForkWork — веб-сайт. Для магазинов приложений нужна обёртка (PWA через Trusted Web Activity для Google Play и RuStore, либо Capacitor), а сам сайт должен быть доступен по https.

## Уже сделано

- Манифест веб-приложения (`/manifest.webmanifest`): название, цвета, режим standalone, ярлыки на сканер, карту, заведения и рецепты.
- Иконки: 192 и 512 px, maskable 512 px, Apple Touch 180 px (`public/icons/`), SVG-значок.
- Метаданные: описание, Open Graph, цвет темы, настройка отображения на телефоне.
- `robots.txt` (закрыты кабинеты, чаты, корзина, API, вход) и `sitemap.xml` (публичные страницы и внешние рецепты).
- Первый заход на главную показывает стрелку на сканер блюда, автоперехода на сканер больше нет.
- Продакшен-база без демо-аккаунтов, постоянный каталог данных, `secure`-cookie (см. `DEPLOY.md`).

## Нужно до подачи (не сделано)

1. **Публичный адрес по https** и переменная `NEXT_PUBLIC_SITE_URL` (нужна карте сайта, `robots.txt` и ссылкам в соцсетях).
2. **Юридические страницы:** политика конфиденциальности, пользовательское соглашение, сведения об источниках данных. Тексты должен проверить юрист: персональные данные, отзывы с чужих сайтов, данные поваров, платежи.
3. **Скриншоты и описание для магазина:** по 3–8 снимков экрана телефона, краткое и полное описание, возрастной рейтинг.
4. **Аккаунты разработчика** выбранных магазинов и подпись приложения (ключ хранить отдельно).
5. **Обёртка** (TWA или Capacitor) и проверка на устройствах. Офлайн-режима и service worker в проекте нет.
6. **Контакт поддержки** и форма обращения (в том числе для поваров, которые хотят исправить сведения о себе).
7. **Ограничение ключа Яндекс.Карт по домену** в кабинете Яндекса.
8. **Проверка скорости и доступности** (Lighthouse) на публичном адресе.
