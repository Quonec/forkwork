# Развёртывание ForkWork на forkwork.online

Проверено локально: сборка `next build`, запуск в режиме продакшена с чистым каталогом данных, `/api/health`, администратор из переменных, отказ демо-входа, `secure`-cookie, заголовки безопасности, `robots.txt` и `sitemap.xml` с адресом сайта. **Не проверено:** сборка Docker-образа (Docker на этом компьютере не установлен), работа на Amvera, DNS и сертификат.

## Порядок

1. **Репозиторий.** Отправьте код в GitHub (`git push origin main`). Конфигурация хостинга лежит в `amvera.yaml` (сборка по `Dockerfile`, порт 3000, постоянный том в `/data`).
2. **Приложение на Amvera.** Создайте приложение из репозитория. Если в панели нужно указать порт и том, это `3000` и `/data`.
3. **Переменные окружения** (раздел ниже). Обязательны `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
4. **Домен.** В панели хостинга добавьте домен `forkwork.online`, а у регистратора создайте DNS-записи, которые покажет хостинг (обычно A или CNAME для `forkwork.online` и `www`). HTTPS-сертификат выпускает хостинг; до его появления сайт по https не откроется.
5. **Проверка.** Откройте `https://forkwork.online/api/health` (ответ `{"ok":true}`), затем главную, `/robots.txt`, `/sitemap.xml`, вход под администратором.
6. **Поисковики и сторы.** После выпуска сертификата отправьте `https://forkwork.online/sitemap.xml` в вебмастера Яндекса и Google.

## Переменные окружения

| Переменная | Нужна | Что делает |
|---|---|---|
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | да, при первом запуске | Единственный аккаунт администратора. Пароль не короче 10 символов. Лучше задавать пароль из латиницы, цифр и знаков: проверялся только такой вариант |
| `DATA_DIR` | задан в `Dockerfile` (`/data`) | Каталог данных; к нему подключён постоянный том. Менять не нужно |
| `CHAT_VAULT_KEY` | желательно | Ключ секретного хранилища чатов без шифрования: base64 от 32 байт (`openssl rand -base64 32`). Без него ключ создаётся в `DATA_DIR/secret/vault.key` |
| `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` | да, при сборке | Ключ Яндекс.Карт. Ограничьте его по домену `forkwork.online` в кабинете Яндекса |
| `NEXT_PUBLIC_SITE_URL` | при сборке, по умолчанию `https://forkwork.online` | Адрес сайта для карты сайта, `robots.txt` и ссылок в соцсетях |
| `SEED_DEMO=1` | нет | Вернуть демо-данные и демо-аккаунты (только для закрытого показа, не для публичного сайта) |
| `NEXT_PUBLIC_SHOW_DEMO=1` | при сборке, в `Dockerfile` по умолчанию 1 | Показать на странице входа значок «Быстрый вход» с демо-аккаунтами заказчика и повара. Работает, только если демо-аккаунты есть в базе (`SEED_DEMO=1`). Для сборки без значка: `--build-arg NEXT_PUBLIC_SHOW_DEMO=0` |
| `NEXT_PUBLIC_SHOW_DEMO_STAFF=1` | при сборке, по умолчанию 0 | Добавить в значок менеджера и администратора. На публичном сайте не включать: это вход в кабинет администратора одной кнопкой |
| `COOKIE_SECURE=0` | нет | Отключить флаг `secure` у cookie (только если сайт открыт по http) |

Переменные с `NEXT_PUBLIC_` вшиваются при сборке образа: после их изменения образ нужно собрать заново.

## Что лежит в `/data`

- `forkwork.db` — основная база (SQLite).
- `secret/vault.key` — ключ хранилища, если не задан `CHAT_VAULT_KEY`.
- `secret/chats/<чат>/<сообщение>.msg` — сообщения чатов с выключенным шифрованием, каждое зашифровано ключом сервера.

Резервная копия должна включать весь каталог: без ключа файлы в `secret/` не прочитать. Автоматического бэкапа в проекте нет: настройте его на стороне хостинга или скриптом.

## Первый запуск

В продакшене (`NODE_ENV=production`) создаются только справочники кухонь и администратор из `ADMIN_*`. Демо-пользователей, поваров и заказов нет, поэтому карта поваров и заказы будут пустыми, пока не зарегистрируются первые повара. Заведения Москвы, топ и рецепты лежат в репозитории (`seed/`) и работают сразу.

## Ограничения

- Одна база SQLite и один экземпляр приложения: горизонтально не масштабируется.
- Запись в чатах и заказах идёт в локальную базу, при потере тома данные теряются.
- Нет мониторинга и автоматического бэкапа. Ограничение попыток входа (5 неудач на почту и 20 на адрес за 15 минут) работает в памяти: при перезапуске сбрасывается, при нескольких экземплярах не общее.
